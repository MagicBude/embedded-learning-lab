# 文档规范

## 基本要求

- 文档以一个明确问题或职责为中心；
- 标题应能独立表达内容；
- 事实、推断、建议和待确认事项应明确区分；
- 避免为了显得完整而加入没有信息量的章节；
- 修改规则、术语、架构或范围时，先检查影响面，再同步更新所有相关规范、决策、导航、正文、图表和项目状态说明；
- 问答和讨论记录不是最终设计文档。结论确认后，应按职责合并到对应文档，不保留重复且容易失效的独立答案副本。

## 文档状态

规划文档使用：

```yaml
---
status: draft | proposed | accepted | superseded
---
```

## 技术内容状态

技术内容的生命周期仍待讨论。候选状态：

```text
capture    原始记录
draft      已开始整理
review     等待验证或审核
verified   关键技术结论已核对
published  允许公开展示
```

## 引用要求

事实依据优先级：

1. 标准、数据手册、参考手册、勘误表和其他官方资料；
2. 官方示例与可重复实验；
3. 教材、论文和可信技术书籍；
4. 高质量文章、课程和视频，用于发现问题与比较解释；
5. AI 只辅助检索、组织和草稿，不作为事实来源。

涉及以下内容时优先引用一手来源：

- 芯片行为、寄存器和位字段；
- 电气参数与时序；
- 协议和标准行为；
- 编译器、RTOS、SDK 和框架语义；
- 安全、可靠性和硬件约束。

不得伪造文档编号、章节、URL、参数或实验结果。

## 术语

- 简体中文为主，标准缩写或行业术语优先；
- 首次出现使用 `DMA（直接内存访问）`、`UART（通用异步收发器）` 等形式；
- 寄存器、位字段、标准名称和代码标识符保持官方原文；
- 不强制在每次出现时重复中文解释。

## 内部链接

- 使用相对路径链接仓库文档；
- 文件移动时更新所有引用；
- 每个新文档应从一个已有导航入口可达；
- 不创建孤立文档。

## 变更交付检查

每次文档变更至少检查：

- 是否改变了已记录决定；
- 是否影响规划门槛、路线图或仓库结构；
- 是否存在使用相同术语或规则的其他文档；
- 是否需要同步图表源文件和 SVG 导出文件；
- 是否需要更新 README 或文档导航；
- 内部链接、格式和 Git diff 是否正常。
