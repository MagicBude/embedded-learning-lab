# 质量与发布规范

## 自动检查

- Sources、主题指南和其他内容的元数据与关系 Schema；
- 重复稳定 ID 与 slug；
- 内部链接、图片、Source ID、精确引用和第三方声明；
- 来源原始 URL、版本、访问方式、许可证和最后核对日期；
- 禁止把 `free` 访问状态当作开放许可证；
- `.drawio` 与 `.svg` 图源配对；
- 课程 manifest、批准产物和校验值；
- 未达到发布条件的内容不得进入网站、搜索、站点地图和 RSS；
- 类型检查、Lint 和自动化测试；
- 静态构建；
- 资源大小和性能预算；
- 基础可访问性。

Schema、链接、发布资格和构建检查是部署前强制项。

## 测试层次

- 内容层：Schema、Source ID、关系、引用定位、许可、状态和发布资格；
- 逻辑层：UART 计算、状态模型和进度迁移；
- 组件层：互动、测验和课程消息桥接；
- 页面层：关键导航、搜索、移动端和键盘流程；
- 构建层：静态产物、Pagefind 范围和 GitHub Pages 路径。

不追求虚假的覆盖率数字；技术计算、发布边界和课程状态必须自动验证。

## 可访问性

以 WCAG 2.2 AA 为目标：

- 键盘可操作且焦点清晰；
- 语义结构正确；
- 文本和控件具有足够对比度；
- 图表有文本替代；
- 信息不只依赖颜色；
- 动画遵守 `prefers-reduced-motion`。

## 浏览器

支持主流桌面与移动浏览器近两个稳定版本。核心阅读与课程导航不依赖实验 API；Web Serial 等后续能力必须渐进增强。

## 性能

- 普通 Knowledge 页面不发送无关课程或实验 JavaScript；
- 普通页面首屏压缩后 JavaScript 暂定目标不超过约 100 KB；
- 互动组件按需加载；
- 图片和图表具有明确尺寸并经过优化；
- 独立课程使用单独大小预算；
- 真实纵向切片完成后基于测量校准预算。

## 发布

主分支由 GitHub Actions 执行检查、public 构建和 GitHub Pages 部署。Pull Request 只运行检查。依赖使用锁文件，小批量更新并完整验证；安全修复优先，框架大版本单独迁移，不自动合并。
