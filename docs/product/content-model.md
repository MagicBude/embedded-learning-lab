# 产品内容模型

本文件定义不同内容类型的长期职责，不代表第一版全部实现。第一版范围由 `first-release-scope.md` 约束。

## Paths

学习路径回答：

> 为了达到一个目标，我应该按什么顺序学习？

路径只组织已有内容，不复制课程或知识正文。

## Knowledge

结构化知识回答：

> 这是什么、为什么存在、如何工作、有哪些边界？

它应成为相对稳定的技术解释来源。

## Courses

课程回答：

> 我怎样循序渐进地学会并练习它？

课程可以包含章节、互动、练习、自测和进度。课程可以从本项目已有 Knowledge、Projects 和 Notes 中产生，也可以从官方资料、书籍、论文、公开文章、公开视频或其他教程的研究中产生。

课程不是外部资料的汇编或改写副本。它需要形成自己的学习目标、知识顺序、解释、练习和验证，并清楚记录来源。

## Labs

实验回答：

> 改变输入、参数或状态后，会发生什么？

实验用于解释时序、状态、信号、拓扑、内存和算法等难以仅靠文字理解的机制。

## Projects

项目回答：

> 如何把知识组织成一个真实、可验证的工程成果？

项目可以关联需求、设计、实现、测试、复盘和发布记录。

## Notes

笔记回答：

> 我遇到了什么、查到了什么、还需要验证什么？

笔记允许不完整，但必须标记状态，不能自动获得公开知识的可信度。

## Tools

工具回答：

> 如何更快、更可靠地完成一个具体工程任务？

工具必须解决真实任务，并关联其依据的知识。

## 来源与内容关系

![来源与内容关系](../assets/diagrams/content-formation.svg)

这张图只表达内容的形成过程，不表达所有交叉引用。课程与 Knowledge 可以互相促进：已有知识可以被组织成课程，课程研究中形成的可靠解释也可以沉淀为 Knowledge。Projects、Labs 和 Tools 同样可以互相引用，但这些关系由元数据和详情页呈现，不画成密集的双向连线。

## 内容成熟生命周期

![内容成熟生命周期](../assets/diagrams/content-lifecycle.svg)

发布不属于成熟度。正式状态以 `content-schema.md` 为准，网站可见性另行记录。

## 第一版取舍

- Knowledge 是稳定技术事实的首选入口；
- Courses 是第一版主要学习入口；
- Labs 首先作为课程或 Knowledge 内的互动，出现真实复用后再提升为独立内容；
- Notes、Projects 和 Tools 保留长期职责，第一版不建设独立网站入口；
- 面试题是策展视图，答案反向引用 Knowledge 和实验依据。
