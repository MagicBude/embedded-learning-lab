# 核心组件规范

本文件定义第一版核心组件的职责、状态和使用边界。实现可以拆分内部结构，但不得改变这里确认的用户可见行为。

## 状态规则

交互组件按实际能力支持以下状态：

| 状态 | 表现要求 |
| --- | --- |
| 默认 | 文字、图标和可点击边界清晰 |
| 悬停 | 只增强边框、背景或文字之一，不产生明显位移 |
| 焦点 | 使用高对比焦点环，不能仅靠浏览器不明显的默认轮廓 |
| 激活 | 表达正在按下，不与“已选中”混淆 |
| 选中 | 同时使用背景或标记与文字语义 |
| 禁用 | 保持可辨认，不响应操作；必要时解释原因 |
| 错误 | 在控件附近提供文字说明，并与对应字段建立语义关联 |
| 加载 | 只用于真实异步操作，保留控件尺寸并阻止重复提交 |

## 按钮和链接

- 每个操作组最多一个主要按钮；
- 次要按钮使用表面背景与边框，低优先操作使用文字或幽灵样式；
- 导航和内容跳转使用链接，不把链接伪装成无语义按钮；
- 图标按钮必须有可访问名称，常用主要操作优先保留可见文字；
- 默认高度 `44px`，紧凑桌面工具可为 `36px`，触摸设备有效目标仍至少约 `44×44px`。

## 输入、搜索与筛选

- 输入框始终有可见标签或明确的程序化名称，placeholder 不代替标签；
- 全局搜索允许直接提交；结果页筛选改变后保留查询词；
- 移动端筛选使用抽屉，并在结果上方列出当前生效条件；
- 验证错误显示在字段附近，焦点移动遵循用户操作而不是自动跳跃。

## 标签与状态

- 内容类型、平台、成熟度和路线状态使用不同的文字前缀或图形，不仅依赖颜色；
- 标签用于信息，不用于执行操作；可操作筛选必须使用按钮或复选框语义；
- 状态名称使用统一词表，不在页面中临时创造同义词。

## 内容卡片与列表条目

- 可进入的精选内容可使用卡片；高密度索引和搜索结果优先使用带分隔线的列表；
- 整张卡片可以点击，但内部存在多个操作时必须拆分清晰交互区域；
- 标题、类型、摘要和关键元数据具有固定阅读顺序；
- 不使用悬停抬升作为唯一可点击提示。

## 导航、目录与面包屑

- 顶部导航只放第一版真实栏目；当前栏目通过文字和视觉标记共同表达；
- 面包屑用于层级定位，不代替页面标题；
- 桌面正文目录跟随滚动但不遮挡内容；移动端使用明确的“本文目录”或“课程目录”入口；
- 课程章节导航与全站导航分离，避免两个导航体系混在同一层级。

## 提示、警告与工程证据

- 普通提示使用中性或主色边界；验证信息使用青绿色；警告使用琥珀色；错误使用红色；
- 每种提示都有标题或类型文字；
- 来源、验证条件、平台限制和已知问题属于正文证据，不藏在 tooltip 中；
- 警告不得只通过整块高饱和背景制造紧张感。

## 代码、表格与技术图

- 代码块包含语言名称和复制操作；只有多行代码显示完整容器；
- 表格使用水平分隔为主，避免密集竖线；窄屏无法重排时局部横向滚动；
- 技术图必须有标题、简短说明和必要的文本替代；
- 图中连线不得穿过无关节点，箭头进入节点边界且指向关系明确；
- 可缩放图在键盘和触摸输入下都能使用，并提供重置入口。

## 进度、自测与反馈

- 进度同时显示数值或章节位置，不能只显示进度条；
- 自测先允许作答，再在题目附近显示反馈和解释；
- 正确与错误同时使用图形、文字和颜色；
- 本地进度提供清除、导出和导入能力，破坏性清除操作需要确认。

## 空、错、加载和不可用

- 空状态说明为空的原因，并提供一个最相关动作；
- 错误状态说明失败对象、重试条件和替代路径；
- 静态内容不显示伪加载骨架；
- `planned` 与 `exploring` 节点保持可阅读但不伪装为现有内容入口；
- 脚本失败时保留正文和必要说明，互动区域提供降级信息。

## 验收要求

- 键盘能够到达并操作所有交互元素；
- 焦点顺序与视觉阅读顺序一致；
- 320px 宽度下无页面级横向滚动；
- 浅色、深色与减少动画模式均经过检查；
- 状态信息在灰度和常见色觉差异下仍可辨认；
- 组件不得引入设计令牌之外的任意颜色、间距、圆角或阴影。
