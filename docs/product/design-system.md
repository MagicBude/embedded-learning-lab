# 网站设计系统

本文件定义 Embedded Learning Lab 的视觉语言、页面骨架和界面组件。实现阶段必须依据本文件构建，不允许在页面开发过程中随意创造互不一致的样式。

Astro 只提供网站技术框架，不负责产品视觉设计。本项目不会把脚手架默认样式当作正式设计。

## 已确认方向

- 整体气质是克制、清晰、可信的“工程学习实验室”，不是营销落地页、传统博客或密集后台；
- 阅读、课程、技术图和互动实验优先于装饰；
- 支持浅色与深色；
- 视觉不能掩盖技术准确性；
- 内容类型必须能够区分，但不依赖颜色作为唯一标识；
- 移动端长课程保留章节定位能力，使用章节抽屉或当前章节入口；
- 参考 Chenxu Qiao 的轻量信息层级，以及嵌问的搜索、练习、成果与验收闭环；
- 不复制参考站的配色、图标、卡片造型、文案或视觉资产；
- 以 WCAG 2.2 AA 为可访问性目标，动画遵守 `prefers-reduced-motion`。

## 已确认视觉基础

### 视觉语言

- 采用克制、清晰、可信且带有工程感的“技术学习实验室”风格；
- 页面首先服务于阅读、查找、练习和实验，不采用后台仪表盘或营销落地页的表达方式；
- 以工程蓝作为主要强调色，青绿色用于实验、完成和验证信息；
- 警示使用琥珀色，错误使用克制的红色；
- 浅色主题使用柔和灰白背景，深色主题使用深蓝灰背景；
- 主要依靠留白、边框和表面层级组织内容，阴影只用于浮层等确有层级需要的元素；
- 卡片只承载可进入、可选择或需要边界的内容，不把普通段落全部包装成卡片。

### 排版与密度

- 中文正文优先使用系统无衬线字体栈，第一版不为装饰目的加载大型 Web 字体；
- 代码、寄存器名、命令和地址使用统一等宽字体栈；
- 页面采用中等偏疏密度，长篇正文目标宽度为 `720–760px`；
- 站点整体内容最大宽度目标为 `1200–1280px`；
- 常规控件和表面使用约 `10–12px` 的中等圆角；
- 图标统一采用 Lucide 风格线性图标，不混用多套图标语言。

### 主题与动效

- 支持浅色、深色和跟随系统，并允许用户手动切换；
- 动效保持短促，只用于状态反馈、空间关系和帮助理解；
- 所有非必要动效在 `prefers-reduced-motion` 下关闭或替换为即时状态变化。

## 设计原则

1. **内容先于界面**：界面帮助理解和导航，不抢夺正文注意力。
2. **结构可以预期**：同类页面使用相同信息顺序和交互位置。
3. **工程证据可见**：来源、验证状态、平台边界和已知限制容易找到。
4. **渐进披露**：先显示学习所需内容，再按需展开来源、追问和高级细节。
5. **状态不靠颜色**：标签同时使用文字、图形或线型表达。
6. **交互按需加载**：普通知识页不承担无关脚本和视觉噪声。

## 需要定义的设计令牌

实现前必须确认：

- 字体族和中英文回退顺序；
- 正文、标题、代码和标注字号层级；
- 行高与正文最大阅读宽度；
- 浅色和深色的背景、表面、文字、边框与强调色；
- 内容类型和状态的颜色与非颜色标识；
- 间距尺度；
- 圆角、边框和阴影级别；
- 内容容器和全宽互动区域的宽度；
- 桌面、平板和移动端断点；
- 动画时长、缓动和减少动画替代方案；
- 图标来源、尺寸与使用边界。

最终令牌应能映射为 CSS 自定义属性，页面和组件不得直接散落未经定义的颜色、字号和间距值。

第一版具体数值见 [`design-tokens.md`](design-tokens.md)。核心组件的状态、职责和验收边界见 [`component-specification.md`](component-specification.md)。实现后的统一检查见 [`visual-acceptance-checklist.md`](../standards/visual-acceptance-checklist.md)。

## 页面模板

### 首页

需要定义：

- 项目定位与主要行动入口；
- 学习路线入口；
- Knowledge、课程和题库的精选区域；
- 全站搜索入口；
- 最近更新是否展示及其视觉优先级；
- 桌面和移动端信息顺序。

已确认的第一版信息顺序：

1. 全站导航；
2. 项目定位、全局搜索和“从学习路线开始”主要入口；
3. 当前学习或继续学习；
4. 四条长期学习分支；
5. 精选课程、Knowledge 和面试题；
6. 最近更新；
7. 项目说明与页脚。

首页不展示虚构统计、无内容的空栏目或仅为填充空间而存在的卡片。

### 路线页

需要定义：

- 路线阶段、依赖与贯穿能力；
- `available / in-progress / planned / exploring` 状态；
- 每阶段目标、产出和验收；
- 规划节点与可进入内容节点的差异；
- 移动端路线的线性替代布局。

### Knowledge 页面

需要定义：

- 标题、摘要、领域、平台、状态和验证时间；
- 前置知识与关联内容；
- 正文、代码、表格、提示、警告和技术图；
- 通用原理与平台实现的视觉分层；
- 来源、验证依据和已知限制；
- 桌面目录与移动端定位入口。

### 课程页面

需要定义：

- 课程介绍页；
- 桌面章节侧栏和移动端章节抽屉；
- 当前位置、上一节和下一节；
- 进度、自测和完成状态；
- 独立课程 HTML 的嵌入边界；
- 关联 Knowledge 的非打断式入口。

### 面试题页面

需要定义：

- 题目、难度、领域、平台和路线阶段；
- 30 秒回答、深入解释、常见追问、易错点和工程证据的渐进展示；
- 练习状态和复习入口；
- 与 Knowledge、课程和实验的关联。

### 搜索页面

需要定义：

- 查询框和键盘行为；
- 内容类型、领域、平台、路线阶段与成熟度筛选；
- 命中片段、空结果和错误状态；
- 移动端筛选布局。

上述页面模板的结构与响应式行为统一以 [`interface-wireframes.md`](interface-wireframes.md) 为准；本文件维护跨页面的视觉和组件规则，不再重复保存另一套页面线稿。

## 核心组件清单

第一版至少需要形成统一规范的组件：

- 全站导航、移动端导航与页脚；
- 搜索框与筛选控件；
- 内容卡片与内容类型标识；
- 状态标签和路线阶段节点；
- 页面目录、面包屑和前后导航；
- 来源引用、验证状态和已知限制；
- 代码块、表格、提示、警告和步骤列表；
- 课程进度、练习反馈和完成状态；
- 空状态、错误状态、加载状态和不可用状态；
- 互动实验的控件、结果和文本替代。

每个组件需要定义默认、悬停、焦点、激活、选中、禁用和错误状态；只有真实存在的交互才实现对应状态。

## 响应式与可访问性

- 从窄屏开始保证正文、导航、表格、代码和互动可用；
- 桌面侧栏在移动端改为抽屉或当前章节入口，不直接消失；
- 所有交互支持键盘，焦点状态清晰；
- 触摸目标保持足够尺寸；
- 图表提供标题、说明和必要的文本替代；
- 颜色对比度满足 WCAG 2.2 AA；
- 动效不是理解内容的唯一方式。

## 设计交付物

进入实现前至少完成：

1. 视觉基调与色彩方案；
2. 排版和间距尺度；
3. 设计令牌表；
4. 桌面与移动端首页线框；
5. Knowledge、课程、路线、题库和搜索的关键页面线框；
6. 核心组件状态表；
7. 浅色和深色示例；
8. 与可访问性、性能规范的对应检查；
9. 实现阶段的视觉验收清单。

## 实现纪律

- 先依据设计令牌建立基础样式，再实现页面；
- 页面只能组合已有模式，新增模式必须先更新本文件；
- 设计变化必须同步影响到的页面、组件、截图、图表和验收标准；
- 不把 Astro 示例主题或第三方组件默认样式直接当作产品设计；
- 实现完成后同时检查桌面、移动端、浅色、深色、键盘和减少动画模式。

## 后续补充

- 互动实验专用控件是否需要在第一条 UART 纵向切片原型后补充。

该项不是进入首个实现纵向切片的阻塞项：只有真实互动原型暴露出通用需求时，才把对应模式提升为设计系统组件。
