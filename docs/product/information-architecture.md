# 信息架构草案

## 首页职责

首页应帮助用户回答三个问题：

1. 这个项目是什么？
2. 我应该从哪里开始？
3. 当前有哪些真实可用的内容？

## 首页结构

```text
首页
├─ 项目定位、全局搜索与路线入口
├─ 当前学习 / 建议从这里开始
├─ 公共主干与四条学习分支
├─ 精选资料、主题指南、课程与面试题
├─ 最近更新
└─ 项目说明与页脚
```

“当前学习”只在本地存在学习进度时显示；首次访问时使用“建议从这里开始”。首页不为尚无真实内容的实验、项目或工具建立空区域。

## 页面线框

本文件只维护栏目职责、页面层级与 URL。首页及其他页面的桌面、移动端结构统一维护在 [`interface-wireframes.md`](interface-wireframes.md)，避免两份线稿产生不同版本。

## 知识领域

- 编程基础；
- 计算机与硬件基础；
- MCU 与裸机开发；
- 接口与通信；
- 实时系统；
- Embedded Linux；
- 网络与 IoT；
- 工程、测试与调试；
- 系统设计与可靠性。

分类用于内容发现，不代表必须按相同名称创建物理目录。

## 导航原则

- 导航只展示已有真实内容的入口；
- 长期架构不直接等于顶部导航；
- 用户可以按路径、主题、内容类型和关联关系发现内容；
- 不以发布时间倒序作为唯一浏览方式；
- 课程、知识、实验和项目应有清晰的视觉类型标识。

## 当前顶部导航

```text
首页｜路线｜资料库｜主题指南｜课程｜搜索｜关于
```

搜索作为独立入口呈现。当前面试题库尚无真实页面，因此不进入导航；窄屏导航自动换行，不能为了容纳入口压缩文字。没有真实内容的 Interview、Labs、Projects、Tools 等长期类型不建立空入口。

## 永久 URL

```text
/paths/
/paths/<slug>/
/sources/
/sources/<slug>/
/knowledge/
/knowledge/<slug>/
/courses/
/courses/<slug>/
/courses/<slug>/<lesson-slug>/
/about/
/search/
```

分类和标签不进入 Sources 或 Knowledge 永久 URL，避免内容调整领域时破坏链接。内部类型 `knowledge` 暂时保留，界面名称改为“主题指南”。

## 首页与视觉原则

- 第一版使用同一公开首页，不建设个人仪表盘；
- 借鉴 Chenxu Qiao 的轻量信息层级，以及嵌问的搜索、练习、成果与验收闭环；
- 不复制参考站的配色、卡片、图标、文案或素材；
- 采用克制的工程学习实验室风格，优先保证排版、技术图和互动可读；
- 移动端长课程使用章节抽屉或当前章节入口，不直接移除定位能力。
