# 资料库与策展规范

## 定位

资料库（Sources）是项目的基础内容层。它保存外部资料的身份、版本、适用范围、许可边界和使用评价，而不是保存未经授权的全文副本。

项目不把自己描述为技术事实的原始权威。项目的核心工作是发现、筛选、核对、组织和连接可靠资料，并通过学习路线、主题指南、课程和实验降低使用这些资料的成本。

## 资料卡回答的问题

每张资料卡至少回答：

- 这是什么资料，由谁维护；
- 它解决什么问题，适合哪个阶段；
- 应该阅读哪一版、哪一章或哪一节；
- 它是规范性依据、官方实现说明，还是二手解释；
- 可以链接、引用、修改或再发布到什么程度；
- 哪些项目内容使用了它；
- 最后一次检查链接和版本是什么时候；
- 已知限制、偏向和替代资料是什么。

## 来源等级

来源等级表达用途，不表达作者或社区的价值高低。

1. `normative`：标准、规范和具有约束力的正式文档；
2. `official`：芯片、工具、框架或项目维护方的手册、源码和培训；
3. `educational`：教材、大学课程、系统教程和经过编辑的培训材料；
4. `practitioner`：工程师文章、技术博客、公开视频和项目复盘；
5. `community`：论坛、问答、讨论串和社区经验。

关键技术结论优先由 `normative` 或 `official` 来源支持。较低等级来源适合发现问题、比较解释和补充实践经验，但不能单独承担高风险结论。

## 免费与许可不是同一件事

资料卡分别记录：

- `access`：`free / registration / mixed / paid`；
- `license`：SPDX 标识、明确的内容许可证或 `all-rights-reserved`；
- `reuse`：允许链接、短引用、修改、翻译、再发布的实际边界；
- `localCopy`：是否允许在仓库保存副本。

“免费阅读”“公开下载”和“可以转载”不得互相替代。许可证不明确时，默认只保存链接、必要的短引用、独立摘要和评论。

## 策展流程

```text
发现候选资料
→ 核对作者、原始链接与版本
→ 判断来源等级和许可
→ 阅读并记录适用范围
→ 与其他来源交叉核对
→ 建立资料卡
→ 关联路线、主题指南、课程或实验
→ 定期检查失效、版本变化与替代资料
```

资料卡进入 `verified` 只表示身份、链接、版本、许可和用途描述已经核对，不表示其中的每一个技术观点都由项目背书。

## 项目内容的引用规则

- 事实性陈述尽量引用到具体章节、页码、条款、提交或版本，不只链接网站首页；
- “来源明确写明”“项目根据来源推导”“项目通过实验观察”必须分开表述；
- 多个来源冲突时保留冲突，不擅自合并成确定结论；
- 主题指南负责比较和导航，不大段重述原文；
- 课程可以增加顺序、例子、练习和反馈，但必须能回到来源与证据；
- 实验结果记录环境、版本、步骤和原始证据，不能外推为所有平台的普遍规律。

## 第一版范围

第一版已经建立 10 张真实资料卡，覆盖 UART 纵向切片、C 标准入口和 GCC、Clang、GDB 工具链入口。资料库索引、筛选、详情和主题指南反向关系已经落地；下一步补充外部链接与版本变化复查，并随真实课程需要继续扩充资料卡。
