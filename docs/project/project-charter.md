# 项目章程

## 项目名称

**Embedded Learning Lab**

中文名称：**嵌入式学习实验室**

## 使命

建立一个能够长期服务个人学习、查阅和工程实践的嵌入式学习实验室，把分散知识和真实实践逐步整理成：

- 可阅读的结构化知识；
- 可练习的渐进课程；
- 可操作的实验与可视化；
- 可追溯的问题记录；
- 可复用的工程经验与工具。

成熟且经过验证的内容可以公开，供其他学习者和工程师参考。

## 首要用户

第一阶段的首要用户是项目作者本人。

公开读者是重要但次一级的用户。项目不应为了追逐平台流量，牺牲个人长期使用价值、技术准确性或可维护性。

第一版采用双层产品形态：Git 仓库承担创作、审核和版本管理，网站承担课程学习、知识查询和公开阅读。项目内容源全部公开，不建设私有内容模式。

## 要解决的问题

- 嵌入式知识分散在教材、官方手册、博客、视频、代码和实际项目中；
- 学过的内容容易遗忘，缺少快速回顾入口；
- 文章、课程、实验和代码彼此割裂；
- 实际问题的排查过程没有被持续沉淀；
- 社交平台适合传播，却不适合作为长期知识主库；
- AI 可以提高整理效率，但容易制造缺少验证的技术内容。

## 产品假设

如果把真实学习和工程活动整理为统一内容源，再根据需要生成文章、课程、实验和平台内容，就能同时降低个人复习成本和公开创作成本。

内容不局限于个人已有项目。官方资料、书籍、论文、公开文章、公开视频和其他课程都可以成为研究输入，但必须经过来源记录、许可判断、重新组织和技术验证，不能把外部内容直接等同于本项目的权威知识。

## 长期内容类型

- Paths：按目标组织的学习路径；
- Knowledge：稳定、结构化的知识解释；
- Courses：可循序学习和练习的课程；
- Labs：解释机制的交互实验和可视化；
- Projects：围绕真实成果组织的工程项目；
- Notes：问题、资料、实验和复盘记录；
- Tools：解决具体工程任务的工具。

## 当前目标

在实现网站之前，完成：

1. 产品边界；
2. 内容模型；
3. 信息架构；
4. 内容生命周期；
5. 课程生成与接入原则；
6. 第一条纵向切片；
7. 技术方案；
8. 验收标准。

当前已完成以上规划讨论，正在把确认结果整理为可执行设计文档。完成规划门槛检查后，仍需用户明确授权才能开始实现。

## 当前非目标

- 构建完整的嵌入式百科；
- 同时覆盖所有芯片、平台和方向；
- 建立社区、论坛或社交网络；
- 建立多用户协作和复杂权限系统；
- 为了展示蓝图而创建空功能；
- 把 AI 聊天框当作核心产品；
- 在内容和流程尚未验证前设计商业化系统。

## 核心原则

1. 个人价值优先，公开价值自然产生。
2. 真实实践驱动，不为填目录而创作。
3. 一个权威内容源，多种呈现形式。
4. 技术事实必须可追溯、可验证。
5. 小而完整优先于大而空泛。
6. 课程和交互必须帮助理解，而不是装饰。
