# 项目决策

本文件记录已经确认的重要决定，并维护仍待讨论的问题。

## 已决定

### D-001 — 项目名称

**状态：accepted**

项目名称使用 **Embedded Learning Lab**，中文名称为“嵌入式学习实验室”，仓库名为 `embedded-learning-lab`。

### D-002 — 当前阶段禁止实现

**状态：accepted**

在规划内容全部讨论完成并得到用户明确授权前，不开始编写产品代码。

### D-003 — 项目目录

**状态：accepted**

后续讨论和项目文件统一在 `D:\Github\embedded-learning-lab` 中进行。

### D-004 — 首要使用方式

**状态：accepted**

项目首先服务个人学习、查阅和工程实践，同时允许成熟内容公开供他人学习。

### D-005 — 课程是正式内容类型

**状态：accepted**

由课程生成流程产生的交互课程将作为网站的一等内容，而不是临时附件。

### D-006 — 文档文件命名

**状态：accepted**

根目录约定文件保留行业惯例大写名称，例如 `README.md` 和 `AGENTS.md`。`docs/` 内普通文档统一使用小写 `lowercase-kebab-case`；各目录的导航文件仍使用 `README.md`。

### D-007 — 课程允许使用外部研究输入

**状态：accepted**

课程不要求必须由项目内部已有知识或工程项目派生。官方资料、书籍、论文、公开文章、公开视频和其他教程都可以成为课程研究输入。

采用外部输入时必须：

- 记录来源和访问版本；
- 判断版权、许可证和可引用范围；
- 区分事实、原作者表达和本项目重新组织的解释；
- 对关键技术结论进行独立核对；
- 避免复制他人的课程结构、正文、图片、代码或练习。

### D-008 — 正式图表的统一格式

**状态：accepted**

正式框图、流程图和架构图统一使用 diagrams.net 维护：仓库保存可编辑的 `.drawio` 源文件，并由 Markdown 引用同名 `.svg` 导出文件。Mermaid 只用于讨论中的临时草图，不作为正式文档图源。

### D-009 — 变更必须同步所有相关文档

**状态：accepted**

每次规则、术语、结构或决定发生变化时，必须检查影响面并同步所有相关规范、决策、产品与架构文档、导航、图表和项目状态说明。规划问答在结论确认后拆分并合并到承担对应职责的设计文档，不长期保留重复的独立问答稿。

## 暂定

无。

## 后续确认的决定

### D-010 — 第一版产品与公开边界

**状态：accepted**

第一版采用“仓库创作与治理 + 网站学习与阅读”的双层形态。仓库和内容源全部公开，不建设私有内容模式；可见性仅使用 `public` 与 `unlisted`，未达到发布条件的内容不得进入正式导航、搜索、站点地图或 RSS。

### D-011 — 第一版内容范围

**状态：accepted**

第一版以 Courses 为主、Knowledge 为辅，并用少量 UART 面试题验证题库模型。Labs 暂时作为课程或 Knowledge 内的互动，不建设空的独立栏目。

### D-012 — 分类、路线与面试题库分离

**状态：accepted**

稳定知识领域、目标学习路线和面试准备是三个相关但不同的视图。题库反向引用 Knowledge、课程和实验依据，不复制一套权威正文。

### D-013 — 第一条纵向切片

**状态：accepted**

第一条纵向切片选择 UART。先补齐数据表示与字节流、C 缓冲区模型、UART 通用原理和 STM32F103 USART 实现四组 Knowledge，再完成课程、互动、实机实验、练习和面试题。

参考平台使用可核验的 STM32F103C8T6 最小系统板，按 64 KB Flash 配置，以 STM32Cube HAL 为主并解释关键寄存器。SWD 调试器与 3.3 V USB-UART 分工，不依赖板载 USB。

### D-014 — 内容权威性与来源优先级

**状态：accepted**

Knowledge 维护稳定事实，课程拥有教学叙事、示例和练习。事实依据优先级为：标准和官方资料；官方示例与可重复实验；教材、论文和可信书籍；高质量二手内容；AI 仅辅助检索、组织和草稿。

旧项目内容不迁移为权威正文，只能作为线索和覆盖度参考。

### D-015 — 内容状态与格式

**状态：accepted**

成熟度使用 `capture / draft / review / verified / archived`；可见性使用 `public / unlisted`；发布时间独立记录。普通内容使用 Markdown 与结构化 YAML，只有真正需要互动的课程章节或实验使用 MDX。

### D-016 — 课程生成与接入

**状态：accepted**

生成课程必须保存 manifest、稳定课程与章节 ID、输入来源和版本、生成器和版本、生成配置、审核记录、批准后的版本化 HTML 产物及校验值。独立 HTML 通过受限制的嵌入容器接入主站，并通过明确消息协议同步进度。

### D-017 — 第一版信息架构

**状态：accepted**

顶部入口为首页、学习路线、知识库、课程、面试题库和关于，搜索为全站功能。第一版不创建没有真实内容的长期栏目或占位页面。

### D-018 — 第一版技术方案

**状态：accepted**

第一版采用 Astro 静态输出、Content Collections/Zod、Markdown/YAML、少量 MDX、Pagefind、npm、GitHub Actions 和 GitHub Pages。简单互动优先原生 TypeScript；复杂互动出现后只选择一个客户端框架，不混搭。

### D-019 — 质量与发布

**状态：accepted**

内容 Schema、稳定 ID、slug、链接、来源、图源配对、课程产物、发布资格、搜索范围、类型、测试、构建、资源预算和可访问性进入自动检查。主分支通过 GitHub Actions 部署；Pull Request 只运行检查。

### D-020 — 许可证

**状态：accepted**

自创代码、构建脚本和互动组件采用 MIT；原创文章、课程正文和图表采用 CC BY-SA 4.0；课程产物按成分延续双许可证；第三方材料保留其原作者、来源、许可和修改记录，不纳入项目自身许可。

### D-021 — 项目连续性

**状态：accepted**

`current-state.md` 是唯一续接入口，配合决策、规划门槛、路线图和 backlog 使用。工作优先级采用 `now / next / later / icebox`。规划访谈记录保留完整选项和回答，用于追溯，不作为当前规则的权威副本。

### D-022 — 实现必须依据网站设计系统

**状态：accepted**

Astro 脚手架不承担产品视觉设计。进入实现前必须确认 `docs/product/design-system.md` 中的视觉基调、设计令牌、关键页面线框、核心组件状态和视觉验收规则；实现不得把脚手架或第三方组件默认样式直接当作产品设计。

### D-023 — 网站视觉基础

**状态：accepted**

网站采用克制、清晰、可信的工程学习实验室风格：工程蓝为主强调色，青绿色表达实验、完成和验证，浅色使用柔和灰白、深色使用深蓝灰；中等偏疏密度，长篇正文约 `720–760px`，整体内容约 `1200–1280px`；以边框和留白建立层级，少用阴影，使用中等圆角和统一线性图标。首页按导航、定位与搜索、当前学习、路线、精选内容、最近更新、项目说明的顺序组织。
