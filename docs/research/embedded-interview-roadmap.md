# 嵌入式学习路线：面试知识路线

本文给出一条面向校招、初级到中级嵌入式软件岗位的完整准备路线。它不是按书名堆知识点，也不假设所有岗位都要求同样深度，而是采用：

```text
共同基础
→ MCU 与裸机主干
→ 工程化与调试
→ 选择一个岗位分支深入
→ 用项目、测量和复盘形成面试证据
```

这份路线服务“面试准备”视图，不取代 `docs/product/learning-roadmap.md` 中的长期能力路线，也不代表站点需要立即为所有节点创建内容。

## 1. 先确定目标岗位

嵌入式岗位的公共基础很大，但后半程差异明显。准备前先选择一个主方向，其他方向保持能解释边界即可。

| 方向 | 典型工作 | 必须深入 | 可以后补 |
| --- | --- | --- | --- |
| MCU / 裸机 / RTOS 固件 | 外设、控制、通信、实时任务、低功耗 | C、MCU、外设、中断、DMA、RTOS、调试 | Linux 内核、复杂网络服务 |
| Embedded Linux 应用 | 串口或网络采集、网关、服务与部署 | C/C++、Linux 系统编程、线程、IPC、网络、调试 | MCU 寄存器细节、内核驱动深入 |
| BSP / Linux 驱动 | 启动、设备树、驱动、板级适配 | C、体系结构、Linux、启动链、设备模型、并发 | 上层业务框架 |
| 网络 / IoT 固件 | 设备连接、协议、安全、OTA | MCU 或 Linux 基础、TCP/IP、应用协议、可靠性 | 内核驱动深入 |

建议只设一个主方向和一个相邻补充方向。例如“MCU / RTOS 为主，网络 / IoT 为辅”，不要同时把四条分支都准备到同一深度。

## 2. 面试能力的四个层级

每个知识点都按四层准备。只达到第一层通常只能应付定义题。

1. **30 秒回答**：准确给出定义、用途和关键边界；
2. **机制解释**：能画数据流、状态图、时序图或内存图；
3. **工程取舍**：能比较方案、资源成本、失败模式和适用条件；
4. **证据证明**：能展示代码、日志、寄存器、波形、测试或故障复盘。

通用回答模板：

```text
它是什么 → 为什么需要 → 如何工作 → 何时不用
→ 常见故障 → 我如何测量或验证过
```

## 3. 共同主干

### M0 — 工具、构建与计算机基础

**学习内容**

- 二进制、十六进制、补码、位运算、大小端；
- CPU、寄存器、内存、总线、缓存、MMIO 的基本关系；
- 编译、汇编、链接、加载，静态库与动态库；
- Git、Make/CMake、交叉编译、GDB 基础；
- 时间复杂度、空间复杂度和常用数据结构。

**高频面试题**

- 从 `.c` 文件到可执行文件经历了什么？
- 声明与定义有什么区别？头文件为什么需要防重复包含？
- 大小端影响什么？如何检测？
- 静态库和动态库有什么区别？嵌入式场景如何选择？
- 交叉编译器、sysroot 和目标根文件系统分别是什么？

**必须产出**

- 用 map 文件解释一个小程序的代码段、数据段和符号地址；
- 用 GDB 完成断点、单步、查看内存、查看调用栈；
- 手写并测试链表、队列、环形缓冲区中的至少两种。

**过关标准**

能从编译错误、链接错误和运行时错误中判断问题发生在哪个阶段，而不是只会重建工程。

### M1 — 嵌入式 C 语言与内存模型

**学习内容**

- 指针、数组、字符串、结构体、联合体、枚举、函数指针；
- 作用域、生命周期、链接属性，栈、堆和静态存储区；
- `const`、`volatile`、`static`、`extern`、`inline`；
- 对齐、填充、严格别名、整数提升、符号扩展；
- 宏与 `inline`、回调、位域及其可移植性；
- 未定义行为、越界、悬空指针、内存泄漏、重入；
- 防御式接口、错误码、资源所有权和单元测试。

**高频面试题**

- 数组名和指针相同吗？函数形参数组为什么会退化？
- `sizeof` 与 `strlen` 的区别是什么？
- `const int *`、`int * const` 和 `const int * const` 如何区分？
- `volatile` 能保证原子性或线程安全吗？为什么不能？
- 结构体大小如何计算？怎样控制和验证布局？
- `static` 修饰局部变量、全局变量和函数分别意味着什么？
- 宏有什么副作用？如何写安全的多语句宏？
- 栈溢出、堆碎片、野指针怎样发现？

**必须产出**

- 可处理二进制零值的缓冲区 API；
- 带满/空处理和边界测试的环形缓冲区；
- 带校验、超时和错误返回的二进制帧解析器；
- 用编译器警告、静态分析或 Sanitizer 找出一个真实缺陷。

**过关标准**

任何指针或缓冲区问题都能画出地址、长度、容量、所有权和生命周期，不用“可能是内存问题”代替分析。

### M2 — 数据结构、算法与状态机

嵌入式面试通常不要求算法竞赛深度，但需要稳定完成基础编码。

**学习内容**

- 数组、链表、栈、队列、哈希表、堆和树的用途与复杂度；
- 查找、排序、二分、位操作、滑动窗口和简单动态规划；
- 有限状态机、查表驱动、生产者—消费者；
- 无动态内存条件下的数据结构取舍。

**练习范围**

- 反转链表、检测环、合并有序链表；
- 环形队列、最近 N 次采样、Top-K 或最小堆；
- 位计数、掩码操作、无符号整数溢出判断；
- 增量式协议解析状态机，能够处理半包、粘包和错误恢复。

**过关标准**

能在白板或在线编辑器中写出边界完整、命名清晰、可测试的 C 代码，并主动说明复杂度和失败条件。

### M3 — 数字硬件、MCU 与 Cortex-M

**学习内容**

- 电压、电流、功耗、逻辑电平、上拉下拉、开漏与推挽；
- 时钟、复位、看门狗、GPIO、存储器映射；
- Cortex-M 运行模式、MSP/PSP、异常、中断向量、NVIC；
- 启动文件、链接脚本、`.data` 搬运、`.bss` 清零、进入 `main`；
- 中断优先级、抢占、临界区、延迟与嵌套；
- HardFault 的现场保存和故障寄存器分析。

**高频面试题**

- MCU 上电后如何运行到 `main`？
- 中断发生和返回时硬件、启动代码和 C 函数分别做了什么？
- 为什么中断服务函数要短？哪些操作不能放在 ISR 中？
- `volatile` 在寄存器和 ISR 共享变量中解决什么，又不解决什么？
- 中断优先级数值与实际优先级是什么关系？
- 看门狗应在何处喂？为什么不能无条件定时喂狗？
- HardFault 如何定位到出错指令？

**必须产出**

- 上电到 `main` 的启动路径图和内存布局图；
- 按键中断、定时器和看门狗实验；
- 一份 HardFault 人为注入与定位记录；
- 用逻辑分析仪或 GPIO 翻转测量一次中断延迟。

**过关标准**

能把“软件函数调用”和“硬件异常进入”清楚区分，并能从参考手册找到寄存器依据。Arm 的异常、屏蔽和栈模型应以对应内核的官方架构与处理器文档为准。

### M4 — 常用外设与通信协议

**学习内容**

- GPIO、EXTI、定时器、PWM、输入捕获、ADC；
- UART：波特率、采样、帧格式、错误、轮询/中断/DMA；
- I²C：起止条件、地址、ACK/NACK、时钟拉伸、开漏；
- SPI：主从、CPOL/CPHA、片选、全双工与时序；
- CAN 基础：仲裁、帧、位填充、错误与过滤；
- DMA：请求、通道、方向、宽度、循环/普通模式和并发边界。

**高频面试题**

- UART、I²C、SPI 如何选？比较线数、拓扑、吞吐和失效模式；
- UART 为什么没有天然消息边界？如何设计接收协议？
- I²C 为什么需要上拉？NACK 可能说明什么？
- SPI 四种模式怎样确定？片选在多字节事务中有什么意义？
- DMA 为什么能减轻 CPU 负担？它是否等于零开销？
- 环形 DMA、双缓冲和 IDLE 检测分别适合什么场景？

**必须产出**

- UART 回环或 CLI，包含超时、溢出和二进制数据处理；
- I²C 或 SPI 传感器驱动，包含断线和错误恢复；
- 定时 ADC 采样，经 DMA 写入缓冲区；
- 每个实验保存正常与失败波形、日志和寄存器证据。

**过关标准**

能沿“协议语义 → 外设控制器 → 引脚电气 → 总线波形 → 软件缓冲区”逐层定位问题。STM32F103 等具体平台的 USART、DMA 和错误标志应直接核对芯片参考手册，而不是只记 HAL 调用。

### M5 — 裸机架构、并发与可靠性

**学习内容**

- super loop、事件驱动、状态机、前后台系统；
- ISR 与主循环共享数据，原子性、临界区和内存可见性；
- 单生产者单消费者环形缓冲区；
- 超时、重试、退避、幂等、错误传播和降级；
- 看门狗、断电恢复、配置持久化、日志和资源预算；
- Bootloader、镜像校验、升级、回滚的基本模型。

**高频面试题**

- 中断和主循环共享变量如何保证正确？
- 关闭中断、原子操作和锁分别有什么代价？
- 如何设计一个不阻塞主循环的串口接收模块？
- 设备死机后如何区分死循环、栈溢出、HardFault 和电源问题？
- 固件升级过程中断电怎么办？如何判断镜像有效？

**必须产出**

- 一个非阻塞数据采集终端；
- 明确模块所有权、事件流和错误恢复的架构图；
- RAM、Flash、栈和周期预算；
- 故障注入清单：断线、超时、溢出、错误帧、复位和断电。

## 4. 分支 A：MCU / RTOS 固件

### A1 — RTOS 核心

**学习内容**

- 任务状态、优先级、抢占、时间片、tick、上下文切换；
- 队列、任务通知、事件组、二值/计数信号量、互斥量；
- ISR-safe API、临界区、调度器锁；
- 优先级反转、继承、死锁、饥饿；
- 任务拆分、资源所有权、栈水位和实时性测量。

**高频面试题**

- 互斥量和二值信号量有什么区别？
- 队列、任务通知和事件组如何选？
- 为什么互斥量通常不能在 ISR 中使用？
- 优先级反转如何发生？优先级继承是否彻底解决？
- 如何估算任务栈？栈溢出怎样发现？
- 高优先级任务为何仍可能响应不及时？

**项目证据**

- 将 M5 裸机项目重构为 RTOS 版本；
- 提供任务表：周期、优先级、栈、阻塞点、共享资源；
- 人为制造一次竞争、死锁或优先级反转并定位；
- 测量任务最坏响应时间和 CPU 占用。

FreeRTOS 官方文档明确区分了用于同步的二值信号量、用于互斥并带优先级继承的 mutex，以及更轻量的直接任务通知。面试回答不应把这些对象只解释成 API 名称。

### A2 — 进阶固件

按岗位选择：低功耗、Flash/EEPROM 仿真、Bootloader/OTA、USB、CAN、BLE/Wi-Fi、DSP/控制、功能安全或安全启动。至少选一个与目标岗位匹配的主题做深，不要全部浅尝。

## 5. 分支 B：Embedded Linux 应用

### B1 — Linux 系统编程

**学习内容**

- 进程、线程、虚拟内存、文件描述符、权限和信号；
- `fork/exec/wait`、管道、共享内存、消息队列；
- pthread、mutex、condition variable、读写锁；
- 阻塞/非阻塞 I/O、`select/poll/epoll`；
- socket、TCP/UDP、字节序、超时和重连；
- GDB、strace、procfs、日志、systemd 服务；
- CMake、交叉编译和部署。

**高频面试题**

- 进程和线程的资源边界是什么？
- mutex 和 condition variable 如何配合？为什么条件要在循环中检查？
- 阻塞、非阻塞、同步和异步是什么关系？
- `select`、`poll`、`epoll` 的差异与适用场景？
- TCP 为什么会粘包？应用协议如何分帧？
- 进程崩溃、内存泄漏和 CPU 占用过高如何排查？

**项目证据**

- 串口采集到 TCP/MQTT 的网关服务；
- 有限状态连接管理、离线缓存、重连和优雅退出；
- 用 strace、GDB 和日志定位至少一个故障；
- 以服务方式部署，并验证设备断连和系统重启后的恢复。

POSIX 把线程定义为同一进程共享地址空间中的多个控制流，并规定同步与线程安全语义；准备时应理解语义，而不只是记 pthread 函数签名。

## 6. 分支 C：BSP / Linux 驱动

### C1 — 启动链与系统构建

**学习内容**

- Boot ROM → Bootloader → Kernel → init → 用户空间；
- 交叉工具链、Kernel、Device Tree、RootFS 的职责；
- U-Boot 基础、内核配置、启动参数和启动日志；
- Buildroot 或 Yocto 的用途、产物和可复现构建；
- 分区、文件系统、镜像烧写和升级。

**高频面试题**

- 上电到用户程序运行经历哪些阶段？
- 设备树解决什么问题？它和驱动代码如何匹配？
- 内核镜像、设备树和根文件系统分别是什么？
- 交叉编译工具链的 libc、headers 和 sysroot 如何配合？
- 启动卡住时如何从日志判断阶段？

Buildroot 官方手册将其职责界定为通过交叉编译生成工具链、根文件系统、内核镜像和 Bootloader；面试中应能指出各产物的位置、用途和目标板部署方式。

### C2 — Linux 驱动与内核并发

**学习内容**

- Linux 设备模型、bus/device/driver/class；
- platform device/driver、设备树匹配、`probe/remove`；
- 字符设备、file operations、sysfs/debugfs；
- MMIO、IRQ、workqueue、timer、wait queue；
- spinlock、mutex、atomic、completion 的上下文边界；
- DMA、cache coherency、引用计数、生命周期和错误清理；
- 模块构建、日志、ftrace、动态调试和崩溃定位。

**高频面试题**

- platform driver 的匹配和 `probe` 过程是什么？
- 设备树节点如何变成设备并与驱动绑定？
- 中断上半部和下半部如何划分？
- spinlock 与 mutex 如何选？哪些上下文可以睡眠？
- `copy_to_user` 为什么不能简单换成 `memcpy`？
- `probe` 中途失败时如何保证资源正确释放？
- DMA 一致性问题从哪里来？

**项目证据**

- 一个设备树描述的 platform 字符设备或真实传感器驱动；
- 用户态测试程序；
- 正常加载、卸载、并发访问、错误路径和重复绑定测试；
- 使用内核日志或 tracing 证明中断、等待和唤醒路径。

Linux 官方文档把驱动绑定描述为 device 与 driver 的匹配过程，匹配成功后调用 `probe()`；platform 总线、资源、生命周期和电源管理都建立在设备模型之上，不能只背字符设备模板。

## 7. 分支 D：网络与 IoT

### D1 — 网络基础

**学习内容**

- OSI/TCP-IP 分层、MAC、ARP、IP、ICMP；
- TCP 握手挥手、序号、确认、流量控制、拥塞控制；
- UDP、DNS、DHCP、HTTP、TLS 的用途与边界；
- socket、网络字节序、分帧、心跳、重连、幂等；
- Wireshark/tcpdump 抓包与时序分析。

**高频面试题**

- TCP 与 UDP 如何选择？“可靠”具体由哪些机制实现？
- TCP 粘包是错误吗？如何设计消息边界？
- 断线重连如何避免重复命令或重复上报？
- 心跳周期怎样决定？网络抖动与设备功耗如何权衡？
- TLS 解决什么问题？证书和设备身份如何管理？

### D2 — IoT 工程

**学习内容**

- MQTT/CoAP、QoS、保留消息、会话与遗嘱；
- 设备身份、凭证保护、时间同步；
- 离线缓存、去重、版本兼容、远程配置；
- OTA 签名、完整性校验、断点续传与回滚；
- 端到端日志、指标和故障定位。

**项目证据**

- 设备或网关到测试服务端的遥测与控制闭环；
- 抓包解释连接、认证、发布与确认；
- 模拟断网、乱序、重复、服务端重启和错误升级；
- 凭证不写死在公开源码，升级失败可恢复。

## 8. 贯穿所有岗位的工程能力

以下内容常被纯题库忽略，却最能区分“做过项目”和“只看过教程”。

### 调试方法

1. 先定义期望、现象和最小复现；
2. 沿数据流划分边界；
3. 为每个边界选择证据：日志、断点、寄存器、波形、抓包；
4. 一次只改变一个变量；
5. 修复后加入回归测试并记录根因。

应熟练使用：GDB、SWD/JTAG、串口日志、万用表、示波器或逻辑分析仪、Wireshark，以及目标分支对应的 strace/ftrace/perf 等工具。

### 测试与质量

- 单元测试、接口测试、板上测试和硬件在环的边界；
- mock/fake/stub 的用途；
- 静态分析、编译器告警、格式化和 CI；
- 边界值、状态覆盖、故障注入和回归；
- MISRA C、CERT C 等规则集的目的，按岗位决定深度。

### 设计与代码评审

- 模块职责、依赖方向、资源所有权；
- 阻塞点、超时和错误传播；
- RAM/Flash/CPU/带宽/功耗预算；
- 可测试接口、可观察性和升级兼容；
- 已知限制、替代方案和选择理由。

## 9. 项目如何变成面试证据

准备 2 个项目即可，但每个都必须能深挖。推荐组合：

1. **共同主干项目**：MCU 数据采集终端，包含传感器、UART CLI、定时采样、缓冲区、错误恢复和测量；
2. **方向项目**：RTOS 固件、Linux 网关、Linux 驱动或 IoT 闭环之一。

每个项目准备一页证据：

- 需求与约束：处理什么、资源和实时要求是什么；
- 架构与数据流：模块、任务/线程、中断、队列和所有权；
- 关键取舍：为什么选中断/DMA、队列/通知、TCP/UDP 等；
- 难点与故障：一个真实问题、错误假设、证据和根因；
- 量化结果：延迟、吞吐、CPU、栈、RAM、Flash、丢包或功耗；
- 验证：测试清单、波形、日志、抓包或故障注入；
- 局限与下一步：诚实说明没有完成或没有验证的部分。

项目陈述使用 STAR 只能组织叙事，不能替代技术证据。面试官继续追问时，应能回到代码、时序和测量。

## 10. 12 周执行计划

适合已有一点 C 基础、每天投入 2–4 小时的人。零基础可把每周扩展为两周。

| 周 | 学习重点 | 可交付结果 |
| --- | --- | --- |
| 1 | M0：数制、构建、链接、GDB | 小程序、map 文件说明、调试记录 |
| 2–3 | M1：C、内存、指针、缓冲区 | 环形缓冲区、帧解析器、边界测试 |
| 4 | M2：基础算法与状态机 | 10–15 道基础编码题、增量解析器 |
| 5 | M3：启动、中断、异常、GPIO/定时器 | 启动图、HardFault 与中断测量 |
| 6–7 | M4：UART、I²C/SPI、ADC、DMA | 三组外设实验及正常/失败证据 |
| 8 | M5：非阻塞架构、可靠性 | 裸机数据采集终端 v1 |
| 9–10 | 目标分支核心 | RTOS/Linux/驱动/网络方向项目 v1 |
| 11 | 调试、测试、资源与性能测量 | 故障注入、量化报告、项目复盘 |
| 12 | 面试整理与模拟 | 题卡、项目一页纸、两轮模拟面试 |

时间不足时，不删共同主干 M1、M3、M4 和调试证据；优先缩小分支广度。

## 11. 每周训练方式

每周按 `40% 学习 + 40% 编码实验 + 20% 复盘表达` 分配：

- 学习：以官方手册、规范和可信教材建立机制；
- 编码：每个概念至少有一个可运行的最小实验；
- 复盘：输出 30 秒回答、机制图、追问和一次失败证据；
- 周末：随机抽 10 题口述，做 1 道 C 编码题，深挖 1 个项目问题。

建立三类卡片：

- **概念卡**：定义、机制、边界；
- **对比卡**：A/B 如何选、代价是什么；
- **故障卡**：现象、假设、证据、根因、修复、回归。

## 12. 最终自检清单

### 共同基础

- [ ] 能解释构建、链接、内存布局和启动流程；
- [ ] 能准确回答 C 指针、存储期、限定符、对齐和未定义行为；
- [ ] 能现场写出边界完整的基础数据结构或状态机；
- [ ] 能解释异常、中断、优先级、临界区和 HardFault；
- [ ] 能比较 UART/I²C/SPI，并展示真实波形或错误证据；
- [ ] 能设计非阻塞数据通路、超时和恢复；
- [ ] 能使用调试器和至少一种硬件测量工具。

### 目标分支

- [ ] MCU/RTOS：能解释调度、IPC、优先级反转、ISR API 和栈测量；
- [ ] Linux 应用：能解释进程线程、IPC、I/O 多路复用、socket 和部署；
- [ ] BSP/驱动：能解释启动链、设备树、设备模型、并发和生命周期；
- [ ] 网络/IoT：能解释 TCP/IP、应用分帧、重连、幂等、安全和 OTA。

### 项目表达

- [ ] 两个项目都能画出架构与数据流；
- [ ] 每个项目至少有一个真实故障复盘；
- [ ] 所有性能和资源结论都有测量方式；
- [ ] 能说明三项取舍和两个已知限制；
- [ ] 简历上的每个技术名词都能接受至少三层追问。

## 13. 资料优先级与推荐入口

技术事实按“标准/官方资料 → 官方示例 → 可信教材 → 高质量二手资料”核对。题库只用于发现遗漏，不能作为事实依据。

### 官方与一手资料

- [Arm Developer Documentation](https://developer.arm.com/documentation)：Cortex-M 架构、异常、寄存器和处理器行为；
- [STM32F103 官方文档入口](https://www.st.com/en/microcontrollers-microprocessors/stm32f103/documentation.html) 与 [RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)：具体芯片外设、寄存器、DMA 与错误标志；
- [FreeRTOS 官方文档](https://www.freertos.org/Documentation/00-Overview)：调度、队列、通知、信号量、互斥量和 ISR API；
- [Linux Kernel Documentation](https://docs.kernel.org/)：设备模型、platform driver、锁、DMA 和驱动 API；
- [Buildroot User Manual](https://buildroot.org/downloads/manual/manual.html)：交叉工具链、根文件系统、内核和 Bootloader 构建；
- [POSIX.1-2024](https://pubs.opengroup.org/onlinepubs/9799919799/)：线程、同步、文件与 socket 接口语义。

### 覆盖度参考

- [嵌问学习路线](https://qianwen-tech.cn/roadmap)；
- [CodeSheep 嵌入式路线图](https://static.r2coding.com/r2_static/pdf/embed.pdf)；
- [0voice EmbeddedSoftwareLearn](https://github.com/0voice/EmbeddedSoftwareLearn)；
- [asia-meidia embedded-interview](https://github.com/asia-meidia/embedded-interview)。

这些二手路线只用于检查主题覆盖，不应直接复制其答案、课程结构或代码。
