Lesson 04 · 第一次实机证据

工具、接线与第一次发送

本课目标：安全连接 STM32F103C8T6 与 3.3 V USB-UART，在 STM32CubeMX/CubeIDE 中配置 USART1，用 HAL 轮询发送固定消息，并保存一份能证明链路工作的终端证据。

1. 先看本课的成功标准

烧录程序后，电脑串口终端每秒稳定显示一行：

UART alive
UART alive
UART alive

“代码编译通过”不能证明 UART 工作；“终端窗口打开”也不能证明数据来自开发板。本课的验收证据是：终端参数、连续输出和程序中的固定消息能够对应，并且复位开发板后输出从头恢复。

2. 每件工具分别做什么

工具本课职责不负责什么
STM32F103C8T6 最小系统板运行程序并由 PA9 输出 USART1_TX不能直接把 UART 电平变成电脑 USB
SWD 调试器下载程序、复位和调试 MCU本课不把它当作串口转换器
3.3 V USB-UART把 PA9 上的 UART 逻辑电平转换为电脑 USB 数据不解释消息内容，也不替代 SWD 烧录
串口终端选择端口和参数，显示收到的字节不能修复错误接线或错误波特率
开发板差异提醒：市场上的 STM32F103C8T6 小板可能来自不同厂家和批次，丝印、晶振、供电跳线及板载电路并不完全一致。芯片引脚功能以 ST 数据手册和参考手册为准，板级供电方式必须同时核对你手中开发板的原理图或说明。

3. 上电前做一次安全体检

  1. 断电接线：先拔掉 USB-UART 和开发板电源，再移动杜邦线。
  2. 确认信号电平：USB-UART 的逻辑电平必须设置或确认为 3.3 V；不要把传统 RS-232 接口直接接入 MCU。
  3. 只保留一个明确电源方案：本实验只连接 USB-UART 的 TX、RX、GND，不连接它的 VCC。开发板由已核对说明的独立方式供电，避免两个电源互相回灌。
  4. 先查标签再接：不同 USB-UART 模块的针脚顺序不同，不能凭颜色或“通常位置”猜测。
  5. 保留 SWD：不要占用 PA13/SWDIO 和 PA14/SWCLK，以便程序异常时仍能重新烧录和调试。
停手条件：无法确认模块逻辑电平、开发板供电入口或 GND 引脚时，不要通电。先查模块型号和板级原理图。

4. 使用 USART1 默认引脚接线

STM32F103 默认映射下，USART1_TX 位于 PA9，USART1_RX 位于 PA10。USART1 也可重映射到 PB6/PB7，但本课不启用重映射。

STM32F103C8T6          3.3 V USB-UART
PA9  / USART1_TX  ───→ RXD
PA10 / USART1_RX  ←─── TXD
GND                 ── GND
                       VCC 不连接

本课只发送，所以真正必需的是 PA9→RXD 和 GND；仍可把 PA10←TXD 接好，为下一课接收与回环做准备。接线完成后用手机拍照或画一张记录，尤其标明模块的电平档位。

5. 在 CubeMX 中配置 USART1

  1. 创建或打开目标为 STM32F103C8Tx 的工程，并确认芯片型号与实物一致。
  2. 在 System Core → SYS 中保留 Serial Wire 调试方式。
  3. 把 Connectivity → USART1 设为 Asynchronous。
  4. 确认引脚图显示 PA9 为 USART1_TX、PA10 为 USART1_RX，没有启用 USART1 remap。
  5. 设置 115200 baud、8 data bits、No parity、1 stop bit、无硬件流控、TX/RX 模式。
  6. 生成工程后检查初始化结构，而不是只相信界面：波特率、字长、停止位、校验、模式和流控应与配置一致。
huart1.Instance = USART1;
huart1.Init.BaudRate = 115200;
huart1.Init.WordLength = UART_WORDLENGTH_8B;
huart1.Init.StopBits = UART_STOPBITS_1;
huart1.Init.Parity = UART_PARITY_NONE;
huart1.Init.Mode = UART_MODE_TX_RX;
huart1.Init.HwFlowCtl = UART_HWCONTROL_NONE;

CubeMX 还会生成 GPIO 和外设时钟初始化。本课使用生成代码建立第一个可观察结果；后续再沿调用路径解释关键寄存器，而不是现在手写一整套初始化。

6. 发送第一条固定消息

把下面代码放入生成器保留的用户代码区域，避免重新生成时被覆盖：

/* USER CODE BEGIN 2 */
uint8_t message[] = "UART alive\r\n";
/* USER CODE END 2 */

/* Infinite loop */
while (1)
{
  HAL_StatusTypeDef status = HAL_UART_Transmit(
      &huart1,
      message,
      sizeof(message) - 1U,
      100U);

  if (status != HAL_OK)
  {
    Error_Handler();
  }

  HAL_Delay(1000U);
}

&huart1 指定 USART1 句柄；message 是发送缓冲区首地址；sizeof(message) - 1U 排除 C 字符串末尾自动附加的 \0；100U 是轮询等待超时，单位为毫秒。

为什么先用轮询发送：它会等待本次数据发送完成，行为直观，适合第一次建立链路。它也会占用 CPU 等待，因此只是教学起点，不是所有场景的最终方案。

7. 在终端中取得证据

  1. 编译并通过 SWD 烧录程序，确认下载无错误。
  2. 在电脑设备管理器或系统端口列表中识别 USB-UART 对应端口，不要靠猜。
  3. 终端设置为 115200、8 data bits、No parity、1 stop bit、No flow control。
  4. 打开端口并复位开发板，观察是否每秒出现一行 UART alive。
  5. 保存截图或文本日志，记录日期、芯片/开发板、端口参数、接线和固件提交。

本课证据包

  • 一张清楚标记 TX、RX、GND 与 3.3 V 档位的接线图或照片；
  • 一张包含串口参数和至少三行连续输出的终端截图；
  • 源码中发送调用所在位置；
  • 一次复位后输出重新出现的观察记录。
为什么要同时保存这四类证据

接线证明物理路径，终端截图证明外部可观察结果，源码证明输出来源，复位实验把持续出现的文本与板上程序联系起来。只有其中一项时，仍可能把旧终端缓存、错误端口或偶然输出误判为成功。

8. 没有输出或出现乱码时怎么排

现象先查什么可验证动作
终端完全无输出端口、GND、PA9→RXD、程序是否运行复位板卡；交换回正确 RXD；用断点确认进入发送调用
稳定乱码双方波特率与帧格式、实际外设时钟双方统一为 115200 8N1；有仪器时测量 0x55 位宽
偶尔缺行供电、接触、复位、发送返回值记录 status；更换可靠导线；观察是否发生复位
下载后仍显示旧文本烧录目标、构建配置、终端缓存修改固定消息并重新全量构建；关闭重开终端

排错时一次只改变一个变量，并记录改变前后的证据。不要同时换端口、改波特率、重接所有线又改代码，否则即使恢复也不知道根因。

9. 自测

建议先独立作答，再逐题展开参考答案。

  1. 为什么本课让 USB-UART 的 VCC 保持不连接？
    点击显示第 1 题答案

    为了让板卡只有一个明确、已核对的供电来源，避免 USB-UART 与另一电源之间互相回灌。本课只需要 TX、RX 和共同 GND 就能传输数据。

  2. PA9 和 PA10 在 USART1 默认映射中分别是什么？
    点击显示第 2 题答案

    PA9 是 USART1_TX，连接 USB-UART 的 RXD；PA10 是 USART1_RX，连接 USB-UART 的 TXD。若启用重映射则会变成 PB6/PB7，因此必须同时检查 CubeMX 引脚图和 AFIO 配置。

  3. sizeof(message) - 1U 为什么要减一？
    点击显示第 3 题答案

    字符数组由字符串字面量初始化时，末尾还包含一个 C 字符串终止符 \0。减一只发送可见消息和 \r\n，不把终止符当作线路数据发送。

  4. 代码编译并烧录成功，是否已经证明 UART 链路成功？
    点击显示第 4 题答案

    没有。它只证明程序可以构建并写入芯片。还必须在正确接线和终端配置下观察到与程序对应的输出，最好再通过复位或波形确认数据确实来自目标板。

  5. 为什么轮询发送适合第一步，却不一定适合最终程序？
    点击显示第 5 题答案

    轮询发送的控制流简单、容易观察，适合建立第一条链路；等待期间 CPU 可能无法处理其他工作，数据量或实时任务增加后通常要比较中断或 DMA 等非阻塞方案。
